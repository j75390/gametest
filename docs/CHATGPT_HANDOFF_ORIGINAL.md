# 운빨원정대 — ChatGPT 인수인계 문서

작성 목적:
이 문서는 지금까지 ChatGPT와 논의한 게임 기획/구현 방향을 Codex/Godot 작업 쪽에 그대로 넘기기 위한 인수인계 문서다.
앞으로 새 기능을 만들 때 이 문서를 기준으로 기존 방향을 깨지 않도록 한다.

---

## 0. 최우선 원칙

- 계획만 적고 끝내지 말고, 기능을 하나씩 실제로 구현한다.
- 각 단계는 반드시:
  코드 작성 → Godot 실행 → 실제 동작 확인 → 오류 수정 → 재실행 → 정상 동작 확인
  순서로 진행한다.
- 임시 이미지/임시 기능을 넣어놓고 완료라고 하지 않는다.
- 없는 기능/에셋은 명확히 미완성으로 표시한다.
- 기존 요구사항을 임의로 축소하거나 바꾸지 않는다.
- 참고 게임/사이트의 디자인·이미지·아이콘을 그대로 복사하지 않는다.
- 참고는 구조/사용성/정보 설계에만 사용하고, 비주얼은 우리 게임의 오리지널 다크 고딕 판타지 스타일로 구현한다.

## 4. 이미지 생성 정책

중요:
- 게임용 이미지 생성은 앞으로 로컬 ComfyUI를 우선 사용한다.
- ChatGPT 이미지 생성 포인트를 불필요하게 소모하지 않는다.
- Codex가 로컬 ComfyUI API(http://127.0.0.1:8188)를 호출하도록 구성한다.

이미지 자산은 기존 종합 시트에서 잘라 쓰지 않는다.
캐릭터별로 실제 독립 자산을 새로 만든다.

캐릭터 기본 자산 예:
- 전신 일러스트 2장
- SD 시트 1장
- 도트 행동/전투 시트 3장
- 카드 아트 여러 장

카드는 반드시:
- 카드 이미지
- 에너지 비용
- 카드명
- 등급/타입
- 실제 효과 설명
이 화면에 보이게 한다.

## 7. 맵

ACT 시작 시 내부적으로 전체 분기형 맵을 랜덤 생성한다.

기본 시야:
- 현재 위치
- 앞으로 약 2줄/2칸 정도만 공개
- 그 이후는 노드/길 자체가 보이지 않게 안개 처리
- 이동하면 새 위치 기준 다음 2칸 공개
- 지나온 길은 계속 표시

유물:
- '탐험가의 지도'
- 현재 ACT의 모든 노드와 연결 경로 공개

멀티에서는 파티원 중 한 명만 가지고 있어도 전체 파티에게 맵이 공개된다.

## 8. 유물

목표:
- 60개 이상

등급:
- 일반
- 고급
- 희귀
- 영웅
- 전설

중요:
유물은 항상 좋은 것만 존재하면 안 된다.

유물 성격:
- 좋은 유물
- 애매한 유물
- 특정 빌드에서만 좋은 유물
- 조건부 유물
- 양날의 검
- 저주 유물
- 함정급 유물
- 파티 공용 유물

예:
- 공격 증가 대신 최대 HP 감소
- 전투 초반 강하지만 장기전 불리
- 포션 슬롯 증가 대신 포션 드랍률 감소
- 첫 상점 상품만 싸지고 나머지는 비싸짐

유물 효과 범위 예:
- PERSONAL: 소유자만
- PARTY: 파티 전체
- GLOBAL_MAP: 맵/원정 전체

소유자는 한 명이어도 공용 효과는 모두에게 적용할 수 있다.

예:
칼리안이 탐험가의 지도를 보유
→ 미라/세라/루시안 포함 전체 파티 맵 공개

공용 유물 중첩 여부는 개별 데이터로 관리한다.

## 9. 유물 설명/기록

효과만 적지 말고 짧은 스토리를 붙인다.

톤:
- Lobotomy Corporation처럼 짧고 의미심장한 기록문
- 불길하거나 세계관 떡밥이 있는 문장
- 설명서/관찰기록 느낌

예:
[탐험가의 지도]

효과:
현재 ACT 전체 지도 공개

기록:
“수많은 원정대가 돌아오지 못했지만,
그들의 마지막 기록만은 이 지도에 남았다.”

특수 유물은:
- 기본 기록
- 획득 이벤트
- 추가 기록
까지 연결 가능

## 10. 이벤트

기본 목표:
- 일반 이벤트 100개 이상
- 캐릭터 전용 이벤트는 캐릭터당 6개

참고:
- Slay the Spire 이벤트의 위험/보상 교환
- Spire Codex의 긴 스토리/연속 선택 구조
- Arknights 로그라이크의 조건부 선택/특수 전투/캐릭터 관련 상황

일반 이벤트:
- 상황 설명 2~4문장
- 선택지 2~4개
- HP / 최대 HP / 골드 / 카드 획득·제거·강화·변환 / 유물 / 포션 / 저주 / 인챈트 / 전투 등을 다양하게 사용

연속/특수 이벤트:
- 스토리를 더 길게 작성
- Stage 1 → Stage 2 → Stage 3...
- 계속 진행할수록 위험/보상 증가
- 중간 이탈 가능
- 조건부 선택지 존재 가능

예:
발견 → 조사 → 위험 감수 → 추가 선택 → 최종 선택

## 11. 캐릭터 전용 이벤트

캐릭터당 6개.

추천 구성:
- 일반 전용 이벤트 3개
- 조건부 전용 이벤트 2개
- 초희귀 연속 이벤트 1개

등장 확률은 낮게 설정.

싱글:
- 현재 캐릭터 전용 이벤트 풀에서 랜덤 선택

멀티:
캐릭터 이벤트 판정이 뜨면 각 플레이어가 자기 캐릭터에 맞는 전용 이벤트를 각각 따로 받는다.

예:
1P 미라 → 미라 전용 이벤트
2P 칼리안 → 칼리안 전용 이벤트
3P 세라 → 세라 전용 이벤트
4P 루시안 → 루시안 전용 이벤트

각자 다른 화면을 보고 개인 결과를 받는다.

## 12. 멀티 파티 이벤트

일반/파티 이벤트는 모든 플레이어에게 같은 이벤트를 보여준다.

진행:
1. 모두 같은 스토리/선택지 확인
2. 각자 비밀 투표
3. 전원 선택 완료 후 투표 공개
4. 가장 많은 표를 받은 선택 실행

동점:
- 동점 난 선택지에 투표한 플레이어 얼굴 아이콘 사이를 빛이 빠르게 이동
- 위/아래 또는 좌/우로 룰렛처럼 이동
- 점점 느려지다가 한 명 얼굴에 멈춤
- 해당 플레이어가 고른 선택지가 최종 선택

예:
1번 2표
2번 2표
→ 동점
→ 얼굴 아이콘 빛 룰렛
→ 선택된 플레이어의 투표안 실행

투표 중에는:
- 누가 어떤 선택을 했는지 숨김
- '선택 완료' 여부만 표시

파티 이벤트 결과 예:
- 전원 HP 변화
- 파티 골드 변화
- 특수 전투
- 공용 유물
- 다음 맵 변화
- 상점/이벤트 확률 변화

## 13. 이벤트 텍스트 연출

Spire Codex의 흔들리는 텍스트 같은 연출을 참고.

공통 EventTextEffect 시스템으로 구현:
- NORMAL
- SHAKE
- STRONG_SHAKE
- WAVE
- PULSE
- FADE
- TYPEWRITER
- PAUSE
- COLOR

예:
[shake]쿵... 쿵...[/shake]

[color=red][shake=strong]
여기서 나가.
[/shake][/color]

중요:
- 모든 문장을 흔들지 않는다.
- 공포/충격/환청/저주/거대한 존재 등장 등 특정 순간에만 사용한다.

## 14. 상점

판매 기능 없음.

상점 판매:
- 카드
- 유물
- 포션
- 카드 제거

카드 제거:
- 상점 방문당 1회
- 진행할수록 가격 증가 가능
예: 75 → 100 → 125...

추가 제거/변환:
- 이벤트
- 특수 유물
- 조건부 선택

일부 저주/봉인/운명 카드는 일반 상점 제거 불가.

- 드로우 방해

## 16. 도감

카테고리:
- 캐릭터
- 카드
- 유물
- 몬스터
- 포션
- 마법부여
- 이벤트
- 파워
- 저주
- 지역

중요한 잠금 규칙:

미등록:
- 검은 실루엣만 표시
- 이름 없음
- 설명 없음
- 희귀도 없음
- 획득처 없음
- 클릭해도 아무 반응 없음
- '클릭 불가' 같은 문구도 표시하지 않음

등록 완료:
- 실제 이미지 표시
- 클릭 가능
- 상세 정보 열림

완성률:
상단에 카테고리별 표시

예:
유물 18 / 80
완성률 22.5%

전체 완성률도 표시 가능.

도감 정보는 실제로 만나거나 획득/조우해야 등록된다.

패배하더라도 이미 등록된 도감 정보는 계정에 남는다.

## 20. 작업 순서

현재 작업은 아래 순서를 최대한 유지한다.

1. 캐릭터 선택 화면
2. 캐릭터 데이터
3. 도감 기본 UI
4. 카드 데이터/카드 도감
5. 유물
6. 포션
7. 마법부여(카드 인챈트)
8. 파워/상태이상
9. 몬스터/엘리트/보스
10. 이벤트
11. 랜덤 ACT 맵
12. 전투
13. 전투 보상
14. 상점
15. 휴식/보물/이벤트 노드
16. 전체 게임 진행 연결
17. 멀티 파티 이벤트/투표/동점 룰렛
18. 오디오/연출 보강

앞 단계가 실제로 작동하지 않으면 다음 단계로 무리하게 넘어가지 않는다.

## 21. 현재 핵심 기획 요약

- 일반 이벤트 100+
- 캐릭터 전용 이벤트 캐릭터당 6개
- 일부는 긴 연속 이벤트
- 멀티 일반 이벤트는 공동 투표
- 동률은 얼굴 아이콘 빛 룰렛
- 멀티 캐릭터 이벤트는 각자 자기 캐릭터 전용 이벤트
- 공용 유물은 소유자 1명이어도 파티 전체 적용 가능
- 탐험가의 지도는 한 명만 가져도 전원 전체 맵 공개
- 유물은 좋은 것만 만들지 않음
- 유물마다 짧은 기록/스토리 추가
- 미등록 도감은 실루엣만, 정보/클릭 없음
- 도감 완성률 표시
- 이벤트 텍스트에 흔들림/색상/타이핑 등 연출 사용
- 이미지 생성은 ComfyUI 중심
- 나중에 BGM/앰비언스/SFX 추가

## 22. Codex에게 마지막으로 강조할 문장

이 문서는 아이디어 참고 문서가 아니라 현재 게임 방향의 인수인계 기준이다.
기존 기능을 임의로 삭제하거나 단순화하지 말고, 이 문서에 적힌 규칙을 실제 Godot 프로젝트에 하나씩 적용한다.

작업 보고 시:
- 실제 변경 파일
- 실제 구현 내용
- Godot 실행 결과
- 남은 미완성 항목
만 명확히 보고한다.
