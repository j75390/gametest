### 4-1. 허브 (신규)

- 도감을 열면 큰 타일 **5개**: `카드 도감` · `유물 보관함` · `포션 연구실` · `몬스터 도감` · **`스토리`**. 아래쪽에 `캐릭터`(지금의 캐릭터 도감 유지), 나중에 `원정 기록`(통계)을 작은 타일로 둔다.

## 6. 스토리 = 연대표 (사용자 제안 반영)

> "도감 스토리를 누르면 어떤 상황이 있고, 해결하면 해금도 되고 스토리도 알 수 있다."

연대표를 따로 메뉴에 두지 않고 **도감의 `스토리` 타일**로 합친다. 구조는 `TIMELINE_DESIGN_2026-10-09.md`(57칸, 에포크, 해금 묶음 3, 확장)를 그대로 쓰되 한 칸의 정체를 **"상황(사건)"**으로 정한다.

**한 칸 = 하나의 상황**

1. **상황(Situation):** 열리기 전에도 *윤곽과 제목 한 줄*이 보인다. 예) 「완치 여섯, 퇴원 없음」 — "병실은 비었는데 장부에는 완치가 적혀 있다."
2. **단서 칸:** 그 상황에 속한 조사 기록(`evidence_*` 121건)이 *단서 슬롯*으로 붙는다. 원정에서 모으면 슬롯이 채워진다. (지금의 "스토리 도감" 글 목록이 여기로 들어온다.)
3. **해결 조건:** 칸마다 한 문장. "장부를 확보한다", "미라로 성당을 끝까지 간다", "점수를 쌓는다".
4. **해결하면:** 칸이 열리며 **이야기 본문**이 나오고 `해금: 카드 ○○, ○○, ○○`(이름·아이콘)이 붙는다. 해금된 콘텐츠는 §3의 *잠김 → 미발견*으로 바뀌어 풀에 들어온다.
5. **0보상 칸(이야기만)** 도 가능.

**화면:** 가로 시간축은 연대표 설계대로(에포크 열, 확장되는 칸). 칸을 누르면 상세 — 위에 장면 그림, 제목·부제, *상황 설명*, *단서 슬롯*, *해결 조건*, (열렸다면) *이야기*와 *해금 목록*.

**기존 연대표 설계와 달라지는 점:** 메인 메뉴 항목은 만들지 않는다(도감 안에서만). "빈칸이 채워진다" 은유는 *단서 슬롯이 채워지는 것*으로 구체화된다. 해금 조건의 정확한 문구는 이 칸 안에서만 공개한다.

2. **스토리 = 연대표 통합:** 메인 메뉴에 연대표를 두지 않고 도감 `스토리`로만 두는 것, 한 칸 = 하나의 상황 + 단서 슬롯 구조.
3. **카드형 틀의 비율:** 유물·포션 카드 168×240 정도가 맞는가(카드 220×330보다 작게).
4. **먼저 할 단계:** P1부터(허브 + 카드). 그림이 늦어도 기존 아트로 먼저 동작하게 만들 수 있다.

## 10. 검토 반영 (Gemini · Codex) — 위 §3·§4·§6·§7을 이 절이 우선한다

**Gemini**

- **3단계 상태 혼동:** 블러(미발견)와 자물쇠(잠김)를 한눈에 못 가릴 수 있다. → 색 언어를 고정한다. **미발견 = 블러 + 보라 테두리 + "미지"**, **잠김 = 자물쇠 + 회청색 + 이름은 보이되 효과 숨김**. 잠김 호버에는 *어느 스토리 칸이 여는지의 한 줄 힌트*("스토리 〈그릇〉에서 열립니다")를 둔다. 해금 순서를 아예 모르면 좌절감만 남는다.
- **유물·포션 카드 가독성:** 168×240 세로 카드는 격자에서 아이콘이 작아지고 텍스트가 빽빽하다. → **격자는 작은 틀 타일**(약 128×168: 이름 리본 + 아이콘 창 + 등급 보석)로, **상세는 클릭/호버 시 큰 카드형 팝업**(168×240 이상, 효과·플레이버·연결)으로 나눈다. 사용자가 원한 "카드형 틀"은 유지하되 격자 밀도를 지킨다.
- **스토리 구조가 복잡하다:** 상황+단서 121칸+조건을 한 화면에 두면 분산된다. → 한 칸의 기본 정보는 **제목·해결 조건·이야기·해금 목록** 넷으로 줄이고, **단서 슬롯은 접히는 보조 영역**으로 둔다. 타일 이름이 설정집으로 오해되지 않게 설명 문구에 "해금"을 직접 쓴다("사건을 해결하면 이야기와 새 기록이 열립니다"). 첫 해금 직후 짧은 안내 한 번.
- **허브 누락:** `키워드(상태이상) 사전`, `이벤트·캐릭터 도감`은 후속 타일로 예약한다(P6). 도감 **완성률(%)**과 **새 해금 빨간 점**을 허브에 둔다.
- **카드 5장뿐일 때의 빈약함:** 필터를 *지금 콘텐츠량에 맞게 줄인다*(유형·희귀도만, 비용·캐릭터 줄은 카드가 늘면 노출). **스토리 칸에 배정된 해금 대기 콘텐츠만** 잠김 슬롯으로 보여 완성 목표를 준다(구현 전 초안은 슬롯으로 내지 않는다).
- **그 밖:** 원본/강화 비교(`강화 상태 보기`), 컨트롤러·포커스 이동 규칙은 P1 설계에 포함.

**Codex**

- **현황 정정 반영:** 개수 표시·스크롤·몬스터 미발견 안내·조건부 스토리 공개는 이미 있다(§1 표 수정). `Codex.tscn`은 탭 구현이 아니라 스크립트 연결 껍데기다. `timeline_progress.json`은 *제안*이며 구현 사실이 아니다.
- **분리 시 깨지는 의존:** `main.gd:1029 show_codex()`는 `Codex` 노드 이름·`closed` 신호·`story_flags`·`card_character`에 의존하고, 978행은 `_change_category("스토리")`를 직접 호출한다. QA는 `_change_category`, `_select`, `_rebuild_list`, `_load_records`, `_catalog_records`, `records`, `category`, `selected_id`, `active_record`와 필터·검색·목록·상세 노드를 직접 쓴다. 영향 QA는 문서의 3개 외에 `story_content`, `story_reader`, `mira_story`, `mira_narrative`, `mira_story_art`, `cathedral_atlas`, `map_viewer`, `poison_split`, `home_merge`, `title_menu`, `mira_motion`까지 이른다. → **호환 어댑터**(기존 공개 멤버를 새 구조 위에 유지)를 먼저 두고, QA는 단계적으로 옮긴다.
- **`review_mode`:** 발견 제한 해제와 `_library` 원고 병합을 담당하며 `_open_review()`가 `get_script().new()`와 부모 상태·포커스 복원을 쓴다. `_navigate(kind,id)`의 분류 이동도 새 화면에서 보존해야 한다.
- **이미 낡은 QA:** `mira_motion_qa`가 요구하는 `sprite_preview/motion_buttons/motion_index/pause_button/playing`은 현재 `codex.gd`에 없다. 이번 재설계로 그 기능을 몬스터·캐릭터 화면에서 *새로 정의*할 기회로 본다.
- **카드 틀 일반화 위험:** `battle_card.gd`는 틀 경로(미라), 크기 220×330, 그림·제목·비용·타입·효과 좌표가 고정이다. 새 틀의 창 영역이 다르면 그림 침범과 문구 겹침이 생긴다 → 틀마다 **창 영역·텍스트 영역을 데이터로** 둔다. 폰트는 Batang/Noto Serif CJK KR/serif 시스템 폴백이라 환경별 줄바꿈이 달라질 수 있다. `int(cost)`는 X 비용에 맞지 않는다. `CardStyle.resolve()`는 소유자 색만 반환하며 현재 카드에서 호출되지 않는다.
- **상태 판정 데이터:** 발견은 `codex_discovery.gd`의 `Discovery.has(kind,id)`(`user://discovered_codex.json`), 미발견은 `codex.gd:_entry()`의 `undiscovered`다. 공용 카드의 발견은 캐릭터별이 아닌 *카드 ID 단위*다. **`unlocked` 개념과 연대표 저장·판정은 현재 없다.** `requires_flag`·`discovery_flag`는 기록 공개 조건이고 콘텐츠 풀 해금과 별개다. `_library` 원고를 잠긴 콘텐츠로 그대로 취급하면 미구현 효과가 섞인다.
- **몬스터 모션:** 지금은 미리보기 불가. `character_assets.json`에 몬스터 모션이 없고 `ash_warden_motions.png`는 연결되지 않은 시트다. 독립 프레임과 재생 시간을 등록한 뒤 `CharacterVisual`로 재생할 수 있다 → 행동 버튼은 모션 등록 몬스터부터.
- **해상도:** 현재 격자는 가용 폭÷222로 열 수를 정한다. 210px 카드 5장은 간격 포함 약 1098px라 1280에서 왼쪽 필터까지 넣기 어렵고 1440에서도 필터 폭을 제한해야 한다. → 필터 패널을 **접히는 패널**로, 카드 열 수를 해상도에 맞춰 4/5로. 720 높이는 스크롤을 전제하고 새 허브·하위 화면마다 두 해상도 렌더 QA를 둔다.
