# 잿빛 원정대 — 통합 인수인계 및 제작 기준

갱신: 2026-10-01. 사용자 요청에 따라 CODEX_HANDOVER ZIP의 기획을 기존 프로젝트 방향에 통합했다. 원문은 CODEX_HANDOVER_ORIGINAL.md, 이전 상세 원문은 CHATGPT_HANDOFF_ORIGINAL.md에 보존한다. 아래는 제작 목표이며 구현 완료 목록이 아니다. 실제 현황·검증은 HANDOFF.md를 따른다.

## 유지하는 최신 결정
- 제목은 잿빛 원정대. 기존 폴더명·GitHub 주소 및 역사 자료의 옛 이름은 유지한다.
- 다크 고딕 덱빌딩 로그라이크, 싱글과 친구 중심 멀티. 참고작은 정보 구조·사용성·분위기의 참고이며 디자인·이미지·아이콘·문구를 복제하지 않는다.
- 캐릭터마다 전용 카드 풀과 독립 전신/선택/초상화/SD/모션/카드 자산을 제작한다. 종합 시트 자르기와 전신 축소로 SD를 대신하지 않는다. 미라의 현재 독립 PNG 12장·6종 타임라인을 보존한다.
- ZIP은 소품 ComfyUI 우선을 제안하지만, 직접 확정한 내장 image_gen 방침은 자동으로 바꾸지 않는다. 도구 전환과 로컬 서버 연결은 별도 결정 사항이다.
- 맵의 두 칸은 연결선 기준 두 번 이동 범위다. 이미 공개한 미선택 분기·연결선도 남긴다. 장소는 아이콘만, 플레이어 위치는 별도 얼굴 표시를 사용한다.
- 실제 공용 원본은 game_data.gd와 data/ JSON이다. 문서의 필드·폴더 예시 때문에 별도 수치 원본을 만들거나 이미 동작하는 구조를 되돌리지 않는다.

## 새로 통합한 제작 목표

### 유물 154개와 고대 유물
기존 60개 이상 목표를 구체화한다: 일반 60 + 고급 40 + 희귀 25 + 영웅 12 + 전설 5 + 고대 12 = 154개. 고대는 유물에 추가되는 구분이며 카드 등급을 자동으로 늘리지 않는다. 저주는 등급과 별도 속성이다.

고대 유물은 캐릭터당 1개, 초희귀 캐릭터 전용 이벤트 체인의 최종 보상이다. 일반 드랍·상점·일반 보스 보상 풀에는 포함하지 않는다. 좋은 효과만 나열하지 않고 조건부/빌드 전용/양날의 검/저주/파티 공용을 구성한다. PERSONAL/PARTY/GLOBAL_MAP 범위와 중첩 규칙, 소유자와 적용 대상을 데이터로 구분한다. 짧은 독자적 기록문·획득 이벤트·숨겨진 추가 기록을 연결한다.

### 콘텐츠 제작 도구와 자산 상태
카드·유물·포션·인챈트·파워·몬스터·이벤트를 사람이 GUI로, 에이전트가 API/CLI로 관리하며 Godot에 내보내는 도구를 목표로 한다. 원문의 API 경로는 설계 예시이며 현재 서버가 존재한다는 뜻이 아니다. 공통 검증/내보내기 계층을 사용하여 게임과 편집기의 데이터가 갈라지지 않게 한다.

자산 상태: draft / generated / needs_review / approved / rejected. 최종 적용은 검증된 approved 자산만 허용하는 흐름을 목표로 한다. 기존 파일 전체를 근거 없이 approved로 표기하지 않는다. 승인 여부와 근거를 기록하며, 이 상태 이름만으로 매번 사용자 중간 승인을 요구하지 않는다.

### 공통 파워/상태이상
플레이어와 일반·엘리트·보스가 같은 시스템을 사용한다. 분류 BUFF/DEBUFF/POWER/CURSE/SPECIAL, 중첩 SINGLE/COUNTER/DURATION/CONDITIONAL을 데이터로 표현한다. HP바 아래 실제 아이콘·중첩 수·남은 턴, hover 툴팁에 이름/분류/중첩/기간/실제 효과를 표시한다. 기존 독·출혈 등의 동작을 보존하면서 공통화한다.

### 이벤트와 멀티
- 일반 이벤트 100개 이상. 캐릭터당 별도 6개(일반 전용 3, 조건부 2, 초희귀 연속 1). 12명 기준 전용 72개 목표다.
- 일반은 상황 2~4문장과 선택 2~4개. 연속 이벤트는 단계·조건·중간 이탈·위험/보상 증가를 지원한다.
- 멀티 캐릭터 이벤트는 각자 캐릭터에 맞는 개인 화면과 결과를 제공한다.
- 공동 이벤트는 동일 선택지에 비밀 투표, 전원 완료 후 공개, 최다 득표 채택. 동점 선택에 투표한 플레이어 얼굴 사이의 빛 룰렛으로 최종 선택을 보여준다. 실제 결과는 호스트에서 한 번 판정·공유하며 이탈/재접속 정책이 필요하다.
- 지도 유물은 파티원 한 명 보유 시 현재 ACT를 전원 공개한다. 실제 네트워크 구현 전에는 다인 마커 테스트와 구분한다.

### 도감·연출·오디오
미등록은 실루엣만 보여주며 이름/설명/등급/획득처/툴팁/클릭 반응을 숨긴다. 검색·필터·관련 항목에서도 미등록 정보가 새지 않게 한다. 등록 시 이미지와 상세정보를 열고 전체/분류별 완성률을 표시한다. 패배 후에도 등록 기록을 저장한다. 저주 분류를 추가하되 기존 스토리는 유지한다.

공통 EventTextEffect는 NORMAL/SHAKE/STRONG_SHAKE/WAVE/PULSE/FADE/TYPEWRITER/PAUSE/COLOR를 지원하는 방향이다. 특정 순간만 사용하며 남발하지 않는다. BGM/전투/UI/이벤트/캐릭터/몬스터/투표 효과음을 구분하고 이벤트에서 음악을 낮추고 앰비언스를 강조한다. 실제 음원 도입 시 라이선스를 확인한다.

## 적용 순서와 검증
원문의 순서(선택→캐릭터 데이터→도감→카드→유물→포션→인챈트→상태→몬스터→이벤트→맵→전투→보상→상점→노드→전체 진행→멀티→오디오)를 기본 계획으로 참고한다. 이미 구현한 기능을 다시 만들지 않고 빠진 항목을 채운다. 도감 영구 해금에는 저장 기반, 멀티 이벤트에는 네트워크 기반이 먼저 필요하다. 사용자의 다음 작업 지시가 우선한다.

이번 반영은 기획/작업 기준과 인수인계 문서 갱신이다. 제작 도구·154개 유물·상태 시스템·멀티 투표·영구 도감은 아직 구현 완료가 아니다. 이후 기능별로 구현→실제 실행→수정→재검증하고 변경 파일/실행 결과/미완성/다음 우선순위를 HANDOFF.md에 갱신한다.
